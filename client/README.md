# Frontend: Корпоративный ИИ-агент по регламентам (Отдел качества)

Веб-приложение для демонстрации корпоративного ИИ-ассистента, работающего строго по регламентам компании с поддержкой Human-in-the-Loop и автономного демо-режима.

---

## 🚀 Быстрый старт

### Требования
- **Node.js**: `v18+` (протестировано на `v20`, `v24`)
- **npm**: `v9+`

### 1. Установка зависимостей
```bash
npm install
```

### 2. Запуск в режиме разработки
```bash
npm run dev
```
Приложение откроется по адресу [http://localhost:5173](http://localhost:5173).

### 3. Сборка для продакшена
```bash
npm run build
```
Собранные статические файлы будут сохранены в папке `dist/`.

---

## 🐳 Запуск в Docker

Сборка легковесного production-образа на базе Multi-stage Dockerfile (`node:20-alpine` → `nginx:alpine`):

```bash
# Сборка образа
docker build -t ai-agent-corp-client:latest .

# Запуск контейнера на 80 порту
docker run -d --name ai-agent-frontend -p 80:80 ai-agent-corp-client:latest
```

После запуска интерфейс доступен по адресу: `http://localhost`.

## 🎯 Проверка 3 обязательных бизнес-сценариев (режим Mock)

По умолчанию приложение запускается в режиме **Mock** и полностью автономно эмулирует бэкенд в `localStorage`.

1. **Кейс 1 — Прямой строгий ответ по регламенту:**
   - Нажмите на чипс: *«Можно ли вернуть лицензию после активации ключа?»*.
   - Агент вернёт зелёный статус **«Подтверждено регламентом»**, чёткий ответ и раскрывающийся блок со ссылкой на *«Регламент возврата и обмена лицензий, п. 4.2»* и цитатой.

2. **Кейс 2 — Уточняющий диалог:**
   - Нажмите на чипс: *«Что делать, если ключ не пришёл, а оплата прошла?»*.
   - Агент вернёт статус **«Требуется уточнение»** и задаст вопрос о длительности ожидания (> 30 минут).
   - Ответьте *«Да, списалось уже час назад»* → получите регламентные шаги по сбою доставки почты (*п. 2.3.1*).

3. **Кейс 3 — Эскалация и дообучение (Human-in-the-Loop):**
   - Нажмите на чипс: *«Можно ли перенести лицензию на другое юрлицо при реорганизации?»*.
   - Агент вернёт статус **«Нет в регламентах • Эскалация»** и карточку с превью письма в Службу качества.
   - Нажмите **«Отправить в Службу качества»** → появится бейдж открытых тикетов в шапке и ссылка **«Открыть в Кабинете СК →»**.
   - Перейдите в **«Кабинет Службы качества»**, выберите созданный тикет, введите эталонный ответ и регламент (например, *«Регламент лицензирования, п. 5.4»*) и нажмите **«Сохранить ответ и пополнить базу знаний»**.
   - Вернитесь во вкладку **«Чат сотрудника»** и задайте тот же вопрос: агент сразу ответит подтверждённой инструкцией из обновлённой базы знаний!

## 🔌 Подключение к реальному бэкенду (Режим API)

1. В правом верхнем углу интерфейса переключите переключатель с **Mock** на **API**.
2. Нажмите на иконку шестерёнки (⚙️) и укажите `API Base URL` (по умолчанию `/api`).
3. При развёртывании в Docker отредактируйте `nginx.conf`, указав IP/хост бэкенда в директиве `proxy_pass http://backend:8000;`.
